# OPTIMIZATION LAB — 初心者向けコンテンツ追加 仕様書

## 0. 背景

現状の `optimization_lab.jsx` は LP（2変数の図解法）からいきなり始まっており、

- 「変数 / 目的関数 / 制約」という**語彙**が未導入
- 「なぜ最適化が必要なのか」という**動機**が未提示
- 「自分で解く」と「ソルバーで解く」の**地続き感**がない

という3つの段差がある。本仕様書は、既存7レッスンの前後に **導入・体感・実務接続** の3層を追加し、
完全な初心者でも「自分が今どこにいるか」を見失わずに走れる構成に再編する。

## 2. 新規レッスン詳細仕様

### 2.1 Lesson 00 `intro` — 最適化って何？

#### 目的
数式を使わずに「決定変数 / 目的関数 / 制約」の3点セットを体に入れる。

#### 題材
**朝のお弁当作り**。決まった時間（20分）と冷蔵庫の中身で、満足度を最大化する。

#### UI 構成
```
┌─ ModuleHeader ─────────────────────────┐
│  LESSON 00 / 最適化って何？            │
│  WHAT IS OPTIMIZATION?                 │
└────────────────────────────────────────┘

┌─ Card / 黒板スタイル ──────────────────┐
│  おかず4種を「いくつ作るか」スライダー │
│   ・卵焼き      [ 0 ─●── 3 ]  個      │
│   ・からあげ    [ 0 ──●─ 4 ]  個      │
│   ・ブロッコリー[ 0 ●─── 4 ]  個      │
│   ・ごはん詰め  [ 0 ──●─ 2 ]  杯      │
│                                        │
│  使った時間  : 18 / 20 分  ✓          │
│  満足度       : 47 ポイント           │
└────────────────────────────────────────┘

┌─ NotePaper ────────────────────────────┐
│ 今あなたがやったこと：                 │
│  ◯ 何を決めた？     → 決定変数        │
│  ◯ 何を最大にした？ → 目的関数        │
│  ◯ 何を守った？     → 制約条件        │
└────────────────────────────────────────┘
```

#### データ
```js
const DISHES = [
  { id: 0, name: '卵焼き',       time: 5, joy: 8,  max: 3 },
  { id: 1, name: 'からあげ',     time: 6, joy: 12, max: 4 },
  { id: 2, name: 'ブロッコリー', time: 2, joy: 4,  max: 4 },
  { id: 3, name: 'ごはん詰め',   time: 3, joy: 6,  max: 2 },
];
const TIME_BUDGET = 20;
```

#### 状態
- `qty: number[]`（各料理の個数、初期値 `[0,0,0,0]`）
- `revealOpt: boolean`

#### ロジック
- 時間合計 / 満足度合計を `useMemo` で計算
- 最適解は **全列挙**（最大 4×5×5×3 = 300 通り）して事前計算

#### 受け入れ基準
- スライダーをいじると即座に時間・満足度が更新される
- 時間オーバー時は警告色（`C.red`）で表示し、満足度を `—` に
- 「最適解を見る」で 3 変数の値が黄色チョーク色で表示される
- 数式（Σ 等）は**一切出さない**

### 2.2 Lesson 02 `explosion` — 組合せ爆発を体感する

#### 目的
「総当たりすればいいじゃん」という素朴発想が、なぜ通用しないかを**桁感で**示す。

#### UI 構成
```
┌─ Card ─────────────────────────────────┐
│  品物の数 n   [ 5 ──●──── 50 ]         │
│                                        │
│  パターン数 :  2^25 ≒ 3,355万 通り    │
│  1台のPCで全部試すと :  約 0.34 秒    │
│  n=50 だと          :  3,570 万年     │
└────────────────────────────────────────┘

┌─ Blackboard / 対数グラフ ──────────────┐
│  y軸 = 計算時間（log）                 │
│  x軸 = n                              │
│  線：① 全探索 2^n                      │
│       ② 動的計画 n·W                  │
│       ③ 線形 n                         │
└────────────────────────────────────────┘
```

#### 状態
- `n: number`（5〜50 のスライダー）

#### ロジック
- `2^n` パターンを `1e9 ops/sec` 仮定で時間に変換
- 単位を秒 → 分 → 時間 → 年 → 億年と動的に切替
- グラフは SVG で 3 本の曲線（指数・多項式・線形）を log スケールで描画

#### 受け入れ基準
- n=20 までは「数秒」、n=30 で「10分超」、n=50 で「宇宙の年齢級」と読める
- グラフは log y 軸で**直線が指数関数**（教育的）
- 「だから賢い解き方が要る → 次レッスン以降」と締めの一文

### 2.3 Lesson 05 `landscape` — 山と谷

#### 目的
貪欲法・山登り法が**局所最適に捕まる**ことを目で見て理解する。
Lesson 06（シフト）の autoSolve が必ずしも最適でない伏線。

#### UI 構成
```
┌─ Card ─────────────────────────────────┐
│  地形：f(x) = sin(2x) + 0.3·x  などの   │
│        凸凹のある1D 関数                │
│                                        │
│  ボールの初期位置 [ 0 ──●─── 10 ]      │
│                                        │
│  [▶ 転がす（貪欲）] [▶ ジャンプ探索]   │
│                                        │
│  到達点 : x=2.1, f=−0.85（局所最小）  │
│  真の最小: x=7.4, f=−1.92             │
└────────────────────────────────────────┘
```

#### 状態
- `startX: number`
- `path: number[]`（軌跡）
- `mode: 'greedy' | 'jump'`

#### ロジック
- 貪欲モード：`x ← x − η·f'(x)` を 50 ステップ
- ジャンプモード：ランダムリスタート 10 回 + 各点で貪欲

#### 受け入れ基準
- 初期位置によって貪欲が異なる谷で止まる
- ジャンプ探索は概ね大域最小に到達する
- 「シフトの自動配置（Lesson 06）も貪欲なので、必ずしも最適ではない」と本文で接続

### 2.4 Lesson 10 `modeling` — 文章を式にする

#### 目的
**読む側から書く側へ**転換する演習。文章中の語句を「変数・目的・制約」のどれかにドラッグ&ドロップ（モバイルではタップ）して仕分ける。

#### 題材（3問構成）
1. ケーキ屋さん（LP系）
2. 配車の割当（割当問題系）
3. 旅行プラン（ナップサック系）

各問の文章例（Q1）：
> 「ショートケーキは1個 **300円の利益** で、**作るのに15分**かかる。
> モンブランは1個 **500円の利益** で、**25分**かかる。
> 営業時間は **8時間まで**。利益を**最大化**したい。」

太字部分が**ドラッグ可能なチップ**になる。

#### UI 構成
```
┌─ Card ─────────────────────────────────┐
│ 問題文（チップ化された語句が散らばる）│
│                                        │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐│
│ │ 決定変数 │ │ 目的関数 │ │  制約    ││
│ │ (空)     │ │ (空)     │ │ (空)     ││
│ └──────────┘ └──────────┘ └──────────┘│
│                                        │
│  [採点] → 正解と解説を表示             │
└────────────────────────────────────────┘
```

#### 状態
- `placement: Record<chipId, 'var' | 'obj' | 'cons' | null>`
- `graded: boolean`

#### 受け入れ基準
- 全チップが分類されると採点ボタンが活性
- 正答チップは `C.green`、誤答は `C.red` で枠
- 全問解いた後、Lesson 11 へ自然に接続する導線

### 2.5 Lesson 11 `toolchain` — ソルバーとモデリング言語

#### 目的
教育用の手作りロジック（既存レッスンの全列挙・貪欲）と、**実務で使う本物の道具**の橋渡し。「どこで何を勉強すればいいか」が分かる出口を作る。

#### コア・メッセージ
> **モデリング言語は「レシピを書く言葉」、ソルバーは「実際に料理する人」。**
> 役割が違うので、両方が要る。レシピさえ書けばコックは入れ替えられる。

#### 比較表（本文中央）
| | モデリング言語 | ソルバー |
|---|---|---|
| 役割 | 問題を**数式に近い形**で書く | 数式を**実際に解く** |
| 例（無料）| PuLP, Pyomo, JuMP, CVXPY | HiGHS, CBC, GLPK, SCIP, Ipopt |
| 例（商用）| AMPL, GAMS | Gurobi, CPLEX, Mosek, Xpress |
| 入力 | あなたが書く | モデリング言語が生成する標準形（MPS/LP/NL） |
| 出力 | （受け流す） | 最適解・最適値・双対 |
| 入れ替え | 同じ言語で別ソルバーに切替可 | 同じソルバーで別言語に切替可 |

#### 同じ問題を3言語で書き比べ
**題材：Lesson 01 のお菓子LP**（既出のため復習にもなる）

タブで切替できるコードビュー：

**(a) 生のLP標準形 (.lp ファイル)**
```
Maximize
 obj: 120 xa + 100 xb
Subject To
 c1: 2 xa + xb <= 12
 c2: xa + 2 xb <= 10
End
```

**(b) Python + PuLP**
```python
from pulp import LpProblem, LpVariable, LpMaximize, value

m = LpProblem("sweets", LpMaximize)
xa = LpVariable("xa", lowBound=0)
xb = LpVariable("xb", lowBound=0)
m += 120*xa + 100*xb
m += 2*xa + xb <= 12
m += xa + 2*xb <= 10
m.solve()  # ← デフォルトは CBC ソルバー
print(value(xa), value(xb), value(m.objective))
```

**(c) Julia + JuMP**
```julia
using JuMP, HiGHS
m = Model(HiGHS.Optimizer)
@variable(m, xa >= 0)
@variable(m, xb >= 0)
@objective(m, Max, 120xa + 100xb)
@constraint(m, 2xa + xb <= 12)
@constraint(m,  xa + 2xb <= 10)
optimize!(m)
```

#### 図解
```
[あなたの問題]
      ↓ モデリング言語で記述（PuLP等）
[標準形 .lp/.mps]
      ↓ ソルバーが読む
[CBC / HiGHS / Gurobi など]
      ↓
[最適解]
```

#### 「どれを選べばいいか」フローチャート
```
最初の一歩？
  └─ Python が書ける  → PuLP + CBC（無料・同梱）
  └─ Julia            → JuMP + HiGHS
  └─ 数式そのまま     → AMPL（商用、無料学生版あり）

商用データで本番運用？
  └─ MIP が遅い       → Gurobi / CPLEX を検討
  └─ 凸QP/SOCP        → Mosek
  └─ 大規模 LP        → HiGHS（無料）でも十分速いことが多い
```

#### 状態
- `langTab: 'lp' | 'pulp' | 'jump'`

#### 受け入れ基準
- 3つのコードが切り替えで見られる（コピペ可能）
- 比較表が読みやすい
- 「同じ問題が、書き方も解き手も差し替えられる」が一読で伝わる
- 本サイトで「全列挙でやっていた」のは教育用で、**実務では PuLP+CBC のように呼ぶだけ**だと明示

## 7. 参考：用語の早見表（本仕様書内で使う定義）

| 用語 | 本サイトでの定義 |
|---|---|
| 決定変数 | あなたが値を決められる量（x, y …） |
| 目的関数 | 最大化 or 最小化したい指標 |
| 制約 | 守るべき等式・不等式 |
| 連続最適化 | 変数が小数OK（LP, QP, NLP） |
| 整数最適化 | 変数が 0/1 や整数（IP, MIP） |
| ソルバー | 数式を実際に解くプログラム |
| モデリング言語 | 問題を数式に近い形で書くためのライブラリ/言語 |
| 全列挙 | 全パターン試す。教育用にはOK、実務はNG |
| 貪欲法 | 各ステップで最良に見える選択を取る。**局所最適に捕まる**ことがある |
